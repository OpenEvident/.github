# Governance

This document describes how decisions are made across OpenEvident projects.

## Current structure

OpenEvident is currently maintained by a single maintainer, who has final say over the direction, roadmap, and merge decisions for each project. This is a practical reflection of where the project is today, not a permanent design choice.

## How decisions are made

Most day to day decisions, such as accepting a pull request or triaging an issue, are made directly by the maintainer based on technical merit, alignment with the project's goals, and code quality.

Larger decisions, such as a breaking change, a new dependency with a restrictive license, or a change in project direction, are discussed in a GitHub issue before being acted on, so the reasoning is public and searchable even when only one person is deciding.

## Becoming a maintainer

There is no formal application process. Maintainer status is offered by the existing maintainer to contributors who have made sustained, high quality contributions over time and have shown good judgment in reviewing others' work. If you are interested, the best path is to keep contributing; it will come up naturally if it fits.

## Adding new maintainers

As additional maintainers join a project, this document will be updated to describe how the group makes decisions, for example by consensus or by a designated lead breaking ties. Until then, the single maintainer model above applies.

## Project scope

Each OpenEvident repository is a separate project with its own scope and roadmap. This governance document describes how decisions are made within a project; it does not imply shared roadmaps or coordinated releases across projects unless a specific repository's documentation says otherwise.

## Changes to this document

This document may be updated as the project and its contributor base grow. Substantive changes will be proposed in a pull request rather than made silently.
